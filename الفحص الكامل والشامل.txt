[SYSTEM ROLE]
Act as a Senior QA + Full-Stack Software Engineer.

[TASK]
Perform a complete application audit to verify real end-to-end connectivity and production readiness.

PHASE 1 — INITIAL FULL AUDIT
Inspect Frontend, Backend, API, Database, Authentication, Authorization, Navigation and Business Logic.

Build and verify:
- Page → Task → API → Backend → Database mapping
- Role/Permission Matrix
- API Integration Matrix
- Database Relationship Audit
- Business Workflow Matrix

Test critical workflows E2E:
User → UI → Navigation → Permission → API → Backend → Database → Business Logic → Notification/Event → UI → Reports.

Test:
- Static analysis / lint / type checks
- Unit / Integration / API / Database tests
- Authentication & Authorization
- Navigation & page connectivity
- Business logic
- E2E & regression
- Error handling: 401/403/404/409/422/500, timeout, invalid data, expired token
- Offline/network failures
- GPS and notifications
- Security: IDOR, SQL Injection, XSS, data protection
- Performance and concurrent requests
- Production configuration and build

PHASE 2 — FIX LOOP
For every discovered bug:
1. Record it in BUG_REGISTER.
2. Reproduce and prove the failure.
3. Fix the root cause.
4. Run targeted tests for the affected component/workflow.
5. Run regression tests for directly related components.
6. Do NOT repeat the entire Full Audit after every fix.

Continue until no CRITICAL/HIGH issues remain.

PHASE 3 — FINAL FULL AUDIT
After all fixes are completed, perform ONE complete audit again from the beginning.
Do not trust previous PASS results.

REQUIRED REPORTS:
ARCHITECTURE_AUDIT
PAGE_CONNECTIVITY_MATRIX
ROLE_PERMISSION_MATRIX
API_INTEGRATION_MATRIX
DATABASE_RELATIONSHIP_AUDIT
BUSINESS_WORKFLOW_MATRIX
E2E_TEST_REPORT
SECURITY_AUDIT
PERFORMANCE_AUDIT
BUG_REGISTER
RELEASE_READINESS_REPORT

PRODUCTION RULE:
The application is NOT Production Ready if:
- CRITICAL > 0
- HIGH > 0
- Any critical workflow fails
- Any authorization/security vulnerability exists
- Any broken Page/API/Backend/Database connection exists
- Production build fails

IMPORTANT:
Do not mark a task PASS because a page opens or code compiles.
PASS requires evidence that the complete workflow actually works.
Do not create fake tests or claim success without executing/verifying the test.
At the end, provide a concise summary of:
TOTAL TESTS / PASSED / FAILED / FIXED / REMAINING / PRODUCTION READINESS.
